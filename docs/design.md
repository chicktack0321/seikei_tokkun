# 公共・政治経済特訓 設計メモ

## 0. 一言でいうと

大学入学共通テスト「公共，政治・経済」の4択問題を、**間隔反復で出し分けながら、
1問ごとに全選択肢の解説を読ませる**アプリ。完全無料・完全オフライン。

## 1. 参考元からの移植マップ

| 移植元 | 何を持ってきたか | 変えたところ |
| --- | --- | --- |
| `ITpassport` | 問題マスター／進捗／日次ログの3モデル、出題順（`StudyQueue`）、習熟度の内訳（`MasteryBreakdown`）、演習の進行と解説パネル、問題一覧、履歴グラフ | 分野・中分類を「公共，政治・経済」の体系へ差し替え。課金（`Entitlements` / `AccessRights` / `PaywallView` / StoreKit）は丸ごと削除 |
| `kobun_app_01` | 完全無料の方針、正本（`data/`）からシードを生成する運用、CIでの生成漏れ検出、TestFlightワークフロー | 正本を単元ごとのファイルに分割。`no` を手動採番にしてIDの固定を明文化 |

課金を落としたことで、`StudyScope.contains` から「購入で使える難易度」の軸が消え、
`QuestionRepository` の出題プールは利用者の設定だけで決まる。
「出題されない理由」が1つ（自分で絞った）に限られるため、画面の案内も分岐が要らない。

## 2. 分野と中分類

試験は「公共」と「政治・経済」の2部構成だが、後者を1つの塊にすると、
利用者にとって最も量の多い経済分野の出来不出来が政治分野に紛れる。
習熟度の主軸として使うため、**公共・政治・経済・国際**の4分野に割っている。

| 分野 | 中分類コード |
| --- | --- |
| 公共 | SEINEN, SHISO, RINRI, SANKA |
| 政治 | MINSHU, KENPO, JINKEN, TOCHI, CHIHO, SENKYO |
| 経済 | TAISEI, SHIJO, SHOTOKU, KINYU, ZAISEI, NIHON, ROUDOU, SHAKAI, SHOHI |
| 国際 | ISEIJI, KOKUREN, IKEIZAI, NANBOKU |

コードは `questionId` に埋め込まれるため改名禁止。単元が増えるときは、既存を変えずにケースを追加する。
`ExamField.scoreWeight` は本試験の配点の目安（公共25 / 政治25 / 経済30 / 国際20）で、
収録の厚みを決める基準として使う。年度ごとに大問構成が動くため、点数そのものではなく目安として扱う。

## 3. データモデル

- `QuestionMaster` … 同梱シードで丸ごとUpsertされる読み取り専用のマスター
- `UserProgress` … 学習履歴。マスターの入れ替えを跨いで**必ず保持する**
- `StudyLog` … 日次の集計。習熟度は現在の状態しか残らないため、その日の値をスナップショットとして焼く

`QuestionMaster` と `UserProgress` は `questionId`（String）でのみ結びつけ、`@Relationship` は張らない。
リレーションを張ると、マスターの delete/upsert が履歴へカスケードしうる。

`curriculumVersion` は「どの課程・どの時点の制度に基づく問題か」を表す。
選挙制度・税率・社会保障の数値は改正で古くなるため、問題ごとに版を持たせて機械的に洗い出せるようにしている。

## 4. 出題

- 1セット10問・制限時間なし。1問ごとに解説を読む時間が乗るため、長くしない
- 出題順は「復習期限が来た問題 → 未学習 → 期限前（期限が近い順）」
- 選択肢は毎回シャッフルする。位置記憶で解けると、間隔反復が測るものが知識でなくなる
- ホームの「復習する問題がN問あります」からは、未学習を混ぜずに期限切れだけを出す（`QuizScope.reviewOnly`）
- 結果画面から「間違えた問題だけ解き直す」へ進める。解き直しは出題範囲も上限も無視して、渡した問題を全部出す

## 5. 解説パネル

このアプリで解説は「おまけ」ではなく学習の本体なので、正誤の表示より面積を取る。読む順に並べる:

1. 正誤と正解の選択肢
2. **自分が選んだ選択肢の解説**（不正解のときだけ。いちばん知りたいのは「なぜ違うのか」）
3. 正解の理由
4. 残りの選択肢の解説（既定は折りたたみ。4本開くと要点が埋もれる）
5. 分野・中分類・難易度・キーワード

共通テストは「もっともらしい誤答」を見分けさせる出題が多い。
誤答選択肢が何を指しているかを示すことが、4択問題の学習価値の半分を占める。

## 6. 習熟度

間隔反復の段階（`UserProgress.reviewBox`）から導き、直近の正誤では反転させない。
1回正解しただけで「習得済み」にすると、翌週には忘れている問題まで習得扱いになり、表示が学習の実態と乖離する。

復習間隔は 0 → 1 → 3 → 7 → 14 → 30 日。7日（box=3）以上に到達した問題を「習得済み」とする。

ホームの分野別習熟度には集計範囲の絞り込みを**適用しない**。
「金融だけに絞ったときの経済分野」のような部分集合を出すと、分野の仕上がりという意味が変わるため。

## 7. 問題データのパイプライン

```
data/questions/<中分類>.json        （正本・人が編集する）
        │  scripts/build_seed.py    （検証しながら結合。version を1つ上げる）
        ▼
SeijiKeizaiApp/Resources/question_master_seed.json
        │  scripts/validate_seed.py （同梱物そのものを検証。CIとSwiftのテストで二重に確認）
        ▼
   アプリ起動時に QuestionMasterSeeder が Upsert
```

検証をスクリプトに集めているのは、データの不備が「実行時に静かに出題されない」形で現れるため。
`version` は生成のたびに1つ上がる。据え置くと、アプリ側が更新を検知せず端末に変更が届かない。

## 8. 完全無料であることの帰結

- StoreKit・課金UI・試用期間の判定を持たない。将来足す予定でも、判定の置き場所だけを残すといったことはしない
- 難易度（基礎／標準／応用）は**出題範囲を絞る軸**であって、解放の境界ではない
- 通信を行わないため、プライバシーポリシーは「収集しない」ことの説明が主になる（`docs/site-content.md`）

## 9. テスト方針

SwiftDataに触れない純粋関数（`StudyQueue` / `StudyHistory` / `MasteryBreakdown` / `UserProgress` の間隔計算）は
そのままユニットテストする。画面まわりは、壊れても画面上は動いて見えるもの
（選択肢シャッフルと正解位置の対応、0問のときの遷移）を `QuizFlowTests` で押さえる。

同梱シードの検査は `SeedValidationTests` がスクリプトと同じ内容で行う。
CIでスクリプトを回すだけだと、ローカルでシードを編集したときに気付けないため二重にしている。
