# 作問のルールとレビュー観点

`data/questions/<中分類コード>.json` に追記する問題の書き方。
生成に生成AIを使う場合も、**出来上がりは必ず人が読んで確かめる**前提で運用する。

## 1. 形式

```json
{
  "no": 13,
  "questionText": "…として、最も適切なものはどれか。",
  "choices": { "A": "…", "B": "…", "C": "…", "D": "…" },
  "correctChoice": "B",
  "explanation": "なぜその選択肢が正しいのかを2〜3文で。",
  "choiceExplanations": {
    "A": "不正解。Aが指しているものを示し、何と取り違えやすいかを書く。",
    "B": "正解。判断の決め手になる一言。",
    "C": "不正解。…",
    "D": "不正解。…"
  },
  "keywords": ["…", "…"],
  "difficulty": 2
}
```

- `no` は**そのファイル内で未使用の整数**を手で決める。既存の番号は絶対に振り直さない
  （`questionId` が動くと、その問題の学習履歴が全ユーザーで失われる）
- `field` と `questionId` は `scripts/build_seed.py` が中分類から組み立てるので、正本には書かない
- `curriculumVersion` は既定を使う。制度改正で一部だけ差し替えるときにだけ問題ごとに指定する

## 2. 機械が落とす条件（`scripts/build_seed.py`）

- 問題文300字以内、選択肢120字以内
- 選択肢はA〜Dの4つ、同じ文言があってはならない
- `explanation` と4本の `choiceExplanations` がすべて埋まっていること
- 正解の解説は「正解」、誤答の解説は「不正解」で始まること
- `difficulty` は 1（基礎）/ 2（標準）/ 3（応用）
- 問題文が他の問題と完全一致していないこと

## 3. 人が見るチェックリスト

1. **正解が本当に一つに定まるか。** 「最も適切なもの」で逃げず、他の3つが明確に誤りだと言えるか
2. **誤答が「事実として正しい文」になっていないか。** 内容は正しいが設問に答えていない選択肢は、
   出題としては成立しても学習者の混乱を招く。誤答は誤りであることを解説で示せるものにする
3. **正解だけが長くなっていないか。** 内容を知らなくても「いちばん詳しい選択肢」を選べば当たる問題になる。
   削るのではなく、誤答を書き足して差をなくす（`build_seed.py` が行数で偏りを警告する）
4. **時点に依存する数値を断定していないか。** 税率・議席数・自給率・高齢化率などは改正や統計更新で変わる。
   「約」「〜を下回る水準」など、更新頻度に耐える書き方にする
5. **制度の「原則と例外」を問えているか。** 共通テストは用語の暗記だけでは解けない。
   例: 「条例には罰則を設けられる」「特別裁判所は設置できない」など、例外・限界に踏み込む
6. **政治的に一方に偏る主張になっていないか。** 制度・事実・学説の説明にとどめ、
   政策の是非そのものを正解にしない
7. **誤答の解説が「何と取り違えたか」を示しているか。** 「不正解。」の後に理由がないと、
   4択問題の学習価値の半分が失われる

## 4. 難易度の目安

| 値 | 段階 | 内容 |
| --- | --- | --- |
| 1 | 基礎 | 教科書の太字レベル。用語の定義をそのまま問う |
| 2 | 標準 | 共通テストの中心。制度の違い、原則と例外、日本と諸外国の比較 |
| 3 | 応用 | 資料読解・計算（信用創造・実質成長率・為替）・複数単元をまたぐ判断 |

収録の目安は 基礎30 : 標準50 : 応用20。`python scripts/build_seed.py --check` で現状の比率を確認できる。

## 5. 生成AIに依頼するときのプロンプト例

```
大学入学共通テスト「公共，政治・経済」の4択問題を10問作ってください。

- 単元: 金融（日本銀行・信用創造・金融政策）
- 難易度: 基礎3問・標準5問・応用2問
- 形式: 問題文300字以内、選択肢は4つで各120字以内
- 各選択肢に解説を付け、正解の解説は「正解。」、誤答は「不正解。」で書き始める
- 誤答の解説には「その選択肢が何を指しているか」「何と取り違えやすいか」を書く
- 正解だけが長くならないようにする
- 税率や統計の数値は、更新されても誤りにならない書き方にする
- 出力はJSONのみ。キーは no / questionText / choices / correctChoice /
  explanation / choiceExplanations / keywords / difficulty
```

生成物は `data/questions/KINYU.json` に追記し、`no` を未使用の番号に振り直してから
`python scripts/build_seed.py` を実行する。
